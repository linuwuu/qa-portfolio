# Анализ требований (Requirements Analysis)

Учебный раздел портфолио: поиск дефектов в требованиях и подготовка уточняющих вопросов до начала разработки и тестирования.

> **Важно:** требования в этой папке сгенерированы ИИ и **намеренно содержат дефекты** (противоречия, пропуски, неоднозначности). Это не реальные проекты, а тренировочный материал. Названия StayNow и ShopLine вымышленные.

## Как устроена работа

1. Читаю требование целиком: описание, бизнес-правила, поля сущностей, API, НФТ.
2. Сверяю части между собой (правила ↔ таблицы ↔ API ↔ поля), ищу, где они расходятся или молчат.
3. Формулирую вопросы, сгруппированные по разделам требования и со ссылкой на пункт (BR-N).
4. В таблице у каждого вопроса указаны:
   - **кому** — аналитик, разработчик или бизнес, чтобы было понятно, кто должен ответить;
   - **приоритет** — что блокирует работу, а что можно уточнить позже.

| Приоритет | Значение |
|-----------|----------|
| критично | без ответа нельзя реализовать или протестировать фичу, есть риск денежной ошибки или утечки доступа |
| важно | влияет на поведение системы и тест-кейсы |
| минор | уточнение, которое не блокирует работу |

## Какие виды дефектов искались

| Вид | Пример из этой папки |
|-----|----------------------|
| Противоречие между разделами | Booking: таблица расчёта говорит «менее 48 часов — возврата нет», а BR-3 даёт 50% |
| Противоречие между правилом и полем | Promo: BR-5 «только один раз» против `per_user_limit` 1–5 |
| Противоречие между правилами | Booking: BR-5 (сбор не возвращается) и BR-6 (при отмене менеджером возвращается полная стоимость) |
| Неоднозначность формулировок | Promo: BR-7 «не суммируется с другими акциями», что такое «другие акции», не определено |
| Дыры в границах значений | Booking: отмена ровно за 24 часа не попадает ни в BR-3, ни в BR-4 |
| Непокрытый граничный случай | Promo: `fixed` до 10 000 ₽ при минимальном заказе 1 000 ₽, скидка может превысить сумму заказа |
| Неописанные ошибки API | Оба кейса: нет ответов на нарушение большинства бизнес-правил, нет 401/403 |
| Неясные роли и права | Booking: может ли менеджер отменить бронь другого отеля; Promo: чей лимит расходует сотрудник поддержки |
| Неопределённые форматы и единицы | Даты без формата, суммы без указания рубли/копейки, часовой пояс |
| Неясный жизненный цикл | Promo: когда засчитывается использование и возвращается ли оно при отмене заказа |

## Связь с тестированием

Из ответов на эти вопросы строятся тест-кейсы: граничные значения (24 и 48 часов, 1000 ₽, лимиты), негативные сценарии по каждому коду ошибки, проверки прав по ролям. Пока на вопросы нет ответов, ожидаемый результат в таких тест-кейсах неизвестен.

## Ограничения

- Заказчика нет, ответов на вопросы нет. Работа заканчивается на этапе вопросов.
- Требования искусственные, поэтому плотность дефектов выше, чем в реальной документации.
